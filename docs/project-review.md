# RAG Tricks 项目审计与改进记录

日期：2026-10-04。

## 项目定位与检查范围

这是静态 RAG 工程知识库，不是实现检索服务的应用仓库。主要资产是 10 个历史主题、63 篇历史知识页（含设计权衡页）、原始材料、来源登记和内容检查脚本。

本次遍历文档结构与链接，重点审阅导航、证据政策、架构概述、索引/检索/生成评估、生成质量及高风险案例，并对原文做局部抽样。未完成所有历史 Claim 的逐条真实性核验。

## 主要发现与处理

| 优先级 | 问题 | 影响 | 已落实处理 |
|---|---|---|---|
| 高 | Recall 分母写错 | 调优指标与 Precision 混淆 | 修正定义，补充算例、空相关集和去重口径 |
| 高 | 相似度被命名为事实准确率/置信度 | 相似但矛盾的回答可能通过质量检查 | 区分证据支持、正确性、完整性与拒答质量 |
| 高 | 来源登记只覆盖 6 页 | 大量精确业务指标看起来像已验证事实 | 历史 63 页全量登记与页面内证据提示；不升级事实状态 |
| 高 | wikilink 无网页渲染支持且存在错误目标 | GitHub/Pages 正文知识网络断开 | 401 处链接迁移为标准链接，修复错名和错目录；无页面的组件名改普通代码文本 |
| 中 | 正则检查误读代码、漏查图片/引用/锚点 | CI 通过不能说明导航有效 | 引入 Markdown 解析、路径边界和锚点检查及回归测试 |
| 中 | 登记结构异常会抛出类型错误 | 检查器崩溃，无法提供完整诊断 | 固定状态集合和字段类型验证，错误汇总输出 |
| 中 | 只有历史调优数字，缺少统一实验协议 | 难复现、难比较、难定位 | 新增评估入口、指标、实验协议和排障四页 |
| 中 | 文档与质量门禁脱节 | 规范只停留在建议 | 所有知识页登记、可达性检查、严格 CI 与维护文档 |

旧检查基线：69 篇 Markdown（包含本地忽略设计稿），22 条 wikilink 提示、52 篇数值密集且缺少证据章节的页面。22 条包含代码示例误报与错误路径，不能等同于 22 个真实断链。

新检查排除本地忽略设计稿和生成目录，对代码示例免检。告警归零来自结构修复与明确标记，历史待核验内容仍单独计数。

## 为什么选择这些改动

保持 Markdown + Jekyll，先解决读者到达页面、判断证据状态和执行验证实验的基本需要。新增一个固定版本的 Markdown 解析库替代自制链接正则，其传递依赖一并固定；维护者需先安装开发依赖。

不引入虚构的服务性能 benchmark。页面中历史 QPS、成本、内部平台名仍需独立审计；新评估流程标为 Derived，指标依据有外部链接和访问日期。

- 检查器回归测试覆盖代码示例、嵌套徽章、图片、引用式链接、中文/重复标题、编码路径、越界路径、歧义 wikilink、异常登记与孤立页面。
- 严格内容检查的复现命令和行为边界见[维护说明](maintenance.md)。
- CI 配置 Python 3.10 / 3.12 双版本测试；远程 CI 是否通过需以实际运行结果为准。
- 原始材料未修改；本次仅审查文本抽取，未声称 PDF 图像复核或完整事实认证。

## 二次复查与修订（2026-10-07）

| 复查发现 | 修复与新增验证 |
|---|---|
| EPUB 文章起点的空 div 被 Pandoc 拆到上一章末尾 | 将稳定 ID 绑定文章标题；校验目标必须是该标题或以该标题开头的 section |
| 新鲜度检查未覆盖 CSS、封面、脚本与来源登记 | 清单升级为 v2，检查全部正文、附录、生成依赖和输出文件 |
| ZIP/清单损坏时可能触发断言或异常退出 | 改为明确诊断；增加无文件、非法 JSON、损坏 ZIP 和过期依赖测试 |
| XMind 嵌套列表的父子关系丢失 | 按列表项层级构建节点，原文备注仍完整保留 |
| frontmatter 与换行可能污染导图标题 | 共用正文提取逻辑，换行保留词间空白 |
| 深层网页缺少统一导航和目录 | 静态主导航、阅读底栏、可折叠目录、中文语言标记和键盘焦点样式 |
| 仅在本地执行 EPUBCheck | 将固定版本、SHA-256 校验及零警告门槛纳入发布流程 |

新增测试覆盖导出内容与目标章节语义，避免“容器合法、锚点存在，但阅读跳转不正确”的假通过。历史 Claim 的证据状态没有因这次工程修订而升级。
