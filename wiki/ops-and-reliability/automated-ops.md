# 自动化运维体系

## 是什么

自动化运维体系是字节跳动基于 DevOps 平台 ByteDevOps 构建的
RAG 系统全流程自动化方案。

涵盖五大核心能力：
- **自动化部署**：蓝绿部署策略，零停机发布
- **索引自动化更新**：影子索引原子切换，不影响线上服务
- **模型自动化迭代**：灰度发布，逐步验证
- **故障自动化修复**：节点下线、显存溢出、检索超时等自动处理
- **资源自动化调度**：GPU、存储、负载基于流量自动调度

该体系将部署时间从天级缩短至小时级，
故障修复时间 ≤ 10 秒，
资源利用率提升 50% 以上。

## 为什么重要

RAG 系统组件众多（数据处理、索引构建、检索服务、生成服务），
手动运维效率低且易出错。

自动化运维解决了三大核心问题：
- **效率**：手动部署需数天，自动化将降至小时级
- **可靠性**：人工操作容易出错，自动化流程标准化且可回滚
- **响应速度**：故障自动修复 ≤ 10 秒，远快于人工响应

在 2024 年双11 大促期间，
自动化运维体系支撑了 QPS = 20000 的业务峰值，
通过动态扩缩容将资源成本节省 45%。

## 如何使用

### 自动化部署与更新

**部署流程**（ByteDevOps）：
1. 开发人员提交代码至 Git 仓库
2. 触发自动化测试（单元测试 + 集成测试，通过率 ≥ 95%）
3. 自动构建 Docker 镜像
4. 镜像命名规范：业务线 - 日期 - 版本号
5. 如 douyin-rag-20240815-v1.2
6. 支持开发/测试/生产三环境部署

**蓝绿部署策略**：
- 先部署新版本至绿环境
- 验证指标（检索召回率、生成准确率无下降）
- 流量逐步切换：10% → 30% → 100%
- 异常则立即回滚至蓝环境

### 索引自动化更新

**定时全量更新**：
- 每日凌晨 2-4 点为索引全量更新窗口
- 自动执行：数据同步 → 向量生成 → 索引重建 → 索引切换
- 使用影子索引确保不影响线上服务
- 完成后原子切换，零停机

**近实时增量更新**：
- 针对高频变化数据（商品库存、实时政策）
- 通过 Kafka + 触发器实现实时更新
- 数据变化后触发向量重新生成
- 索引更新延迟 ≤ 2 秒

**更新校验**：
- 每次更新后自动抽取 1000 条样本进行检索测试
- Recall@10 ≥ 90% 方可完成更新
- 否则自动触发回滚

### 模型自动化迭代

**数据收集**：
自动从"生成质量反馈库"和人工评估报告收集优化数据，
每周自动生成微调数据集。

**模型训练**：
使用分布式训练平台 ByteTrain，
自动执行数据预处理 → 模型微调 → 模型评估流程。

**灰度发布**：
- 新模型部署至 10% 流量的生成服务
- 对比新旧模型质量（事实准确率、幻觉率）
- 对比新旧模型性能（latency、QPS）
- 指标达标后全量发布，否则自动回滚

### 故障自动化修复

**节点下线**：
检测到向量数据库从节点下线后，
自动触发"节点重启 → 数据同步 → 重新加入集群"流程，
修复时间 ≤ 10 秒。

**GPU 显存溢出**：
检测到 GPU 显存占用 ≥ 95% 时，
自动杀死低优先级进程（如非实时生成任务），
释放显存并触发告警。

**检索超时**：
检索响应时间 ≥ 1s 的请求占比 ≥ 5% 时，
自动增加向量数据库从节点数量。

**数据同步失败**：
数据层同步延迟 ≥ 30s 时，
自动重启同步服务，
失败则切换至备用数据源。

### 资源自动化调度

**GPU 调度**：
实时监控 GPU 使用率。
当某业务线使用率 ≥ 85% 且预测未来 1 小时流量增长 ≥ 20%，
自动从低优先级业务抢占空闲 GPU 或触发云扩容。

**存储调度**：
ByteVectorDB 某分片存储使用率 ≥ 80% 时，
自动将冷数据（近 3 个月未检索）迁移至对象存储 OSS。

**负载均衡**：
ByteLB 自动检测节点负载。
当某节点 CPU 使用率 ≥ 80% 时，
将新请求分配至低负载节点，避免单点过载。

## 常见误区

**索引更新停服**：须采用影子索引 + 原子切换，避免更新时中断线上服务。
**模型直接全量发布**：新模型须经 10% 灰度验证再全量，防止大规模质量下降。
**冷热数据不分层**：应构建冷热数据分层存储，冷数据自动迁移至低成本存储。
**缺乏更新校验**：每次更新后须自动执行质量校验，不达标则回滚。
