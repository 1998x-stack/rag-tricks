# 全链路监控体系

> **证据状态：Unverified。** 本页为历史整理，尚未逐条核验；公司实践、组件名称与精确指标均不能直接作为已证实事实或通用基准。见本页「来源与证据」。

## 是什么

全链路监控体系是字节跳动围绕 RAG 系统
"数据层 - 索引层 - 检索层 - 生成层"四层架构
构建的多维度监控体系。

该体系覆盖四大监控维度：
- **性能维度**：响应时间、QPS、吞吐量
- **质量维度**：准确率、召回率、幻觉率
- **资源维度**：CPU、内存、GPU、存储使用率
- **业务维度**：调用量、成功率、投诉率

通过 ByteMonitor（实时监控）、ByteLog（日志分析）、
ByteProfiler（性能分析）等工具实现秒级数据采集、
全链路日志追踪与性能瓶颈定位，
确保系统问题可发现、可定位、可追溯。

## 为什么重要

RAG 系统涉及多层组件协同
（数据处理 → 索引构建 → 向量检索 → 模型生成），
任何一层的性能劣化或故障都会影响整体服务质量。

缺乏全链路监控会导致：
- 故障发现滞后（问题出现数小时才被发现）
- 根因定位困难（需人工排查多层日志）
- 问题追溯无依据（缺乏链路数据）

字节跳动通过该体系将故障发现时间从分钟级缩短至秒级，
异常检测准确率 ≥ 98%，误报率 ≤ 0.5%。

## 如何使用

### 四层监控指标体系

**数据层监控（实时）**：
- 数据质量：清洗错误率 ≤ 0.5%，更新延迟 ≤ 10 秒
- 数据完整性 ≥ 99.9%
- 存储性能：数据库读写 latency
- 存储使用率 ≤ 80%，IOPS ≥ 1 万

**索引层监控（每小时）**：
- 索引性能：向量生成 latency ≤ 200ms
- 索引构建耗时 ≤ 4h（1 亿数据）
- 索引更新延迟 ≤ 2s
- 索引质量：向量相似度准确率 ≥ 95%
- 召回率（Recall@10）≥ 90%

**检索层监控（实时）**：
- 检索性能：平均响应时间（ART）≤ 500ms
- QPS ≥ 1 万，超时率 ≤ 0.1%
- 检索质量：精确率（Precision@10）≥ 85%
- MAP ≥ 88%，二次检索率 ≤ 10%

**生成层监控**：
- 生成性能：latency ≤ 1s（实时业务）/ ≤ 3s（非实时）
- QPS ≥ 5000，GPU 使用率 ≤ 85%
- 生成质量：事实准确率 ≥ 90%，幻觉率 ≤ 5%
- 用户满意度 ≥ 85%，格式符合度 ≥ 95%
- 业务指标：成功响应率 ≥ 99.99%
- 用户投诉率 ≤ 2%
- 资源指标：CPU ≤ 80%，内存 ≤ 85%，显存 ≤ 90%

### 监控工具链

**ByteMonitor**：
实时监控平台，秒级数据采集与多级别告警（P0-P3），
覆盖系统指标与业务指标。

**ByteLog**：
日志收集与分析平台。
收集全链路日志（数据处理日志、检索日志、生成日志）。
支持按"请求 ID"追踪完整链路，快速定位故障点。

**ByteProfiler**：
性能分析工具。
对检索层、生成层进行性能采样。
定位向量数据库检索耗时过长、GPU 推理卡顿等瓶颈。

**质量评估工具**：
ByteRetrievalEval 自动计算检索质量指标。
ByteGenEval 自动计算生成质量指标。
均可生成可视化报告。

### 异常检测

采用"静态阈值 + 动态基线"结合的算法：

**静态阈值**：
- CPU 使用率 ≥ 95%
- 磁盘使用率 ≥ 85%
- 内存占用 ≥ 90%
用于明确异常的快速检测。

**动态基线**：
- 检索 latency 突然升高 50%
- 超出历史同期 3 倍标准差
- 日调用量环比下降 30%
用于趋势性异常的智能识别。

异常检测准确率 ≥ 98%，误报率 ≤ 0.5%。

### 可视化仪表盘

构建 RAG 系统专属监控仪表盘：

**全链路概览**：
展示系统调用量、成功响应率、平均 latency，
支持按业务线（抖音电商/飞书/金融）筛选。

**层级详情**：
- 数据层：更新延迟、存储使用率
- 索引层：构建进度、向量生成效率
- 检索层：QPS、响应时间分布
- 生成层：GPU 使用率、生成质量趋势

**告警中心**：
实时展示未处理告警，按紧急程度（P0-P3）排序。
P0 级告警红色高亮，
支持一键查看告警详情与处理建议。

## 常见误区

**监控层级不完整**：须覆盖全部四层（数据层、索引层、检索层、生成层），不可遗漏。
**仅用静态阈值**：须结合动态基线检测，以历史分布为参考识别趋势性异常。
**告警泛滥**：应实施告警分级（P0-P3），不同级别使用不同通知渠道。
**指标粒度过粗**：核心指标应实施秒级采集而非每小时计算。
