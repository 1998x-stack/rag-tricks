# 性能压测实践

## 是什么

性能压测是验证 RAG 系统在高并发、大数据量场景下
稳定性的关键环节。

字节跳动使用自研分布式压测工具 BytePress，
建立了覆盖四大场景的标准化压测流程：
- **并发量压测**：逐步提升 QPS，验证系统承载上限
- **峰值流量压测**：模拟双11 等突发峰值，验证抗压能力
- **长时间稳定性压测**：24 小时持续压测，排查内存泄漏
- **故障注入压测**：主动注入故障，验证容错和恢复能力

配合完整的压测指标体系，确保系统上线前满足业务峰值需求。

## 为什么重要

RAG 系统在双11、春节等业务高峰期面临突发流量冲击。
未经充分压测的系统可能在高并发下出现
响应时间飙升、服务不可用、数据丢失等严重问题。

通过标准化压测体系，字节跳动成功将
抖音电商客服系统的 QPS 承载能力从 15000 提升至 30000，
2024 年双11 期间平稳支撑了 QPS = 20000 的业务峰值。

## 如何使用

### 压测环境与数据准备

**环境搭建**：
压测环境 1:1 复刻生产环境。
包括 CPU 型号、GPU 型号/数量、内存大小、
网络带宽、ByteVectorDB 分片数、Redis 缓存配置。
与生产环境通过 VPC 物理隔离，
压测流量不影响线上服务。

**数据准备**：
从生产环境同步全量知识库数据。
向量数据库数据量与生产一致（如 50 亿级向量）。
基于近 3 个月真实查询日志，
按"业务类型 × 查询复杂度 × 检索频率"三维度抽样，
生成 10 万条压测用例。
高频查询（如"报销流程""商品尺码"）占比 40%，
模拟业务峰值的查询分布。

### 四大压测场景

1. **并发量压测**：
   逐步提升并发请求数（1000 → 30000 QPS）。
   每级停留 10 分钟。
   监控不同并发下的响应时间、成功率、资源使用率。
   验证系统 QPS 承载上限。

2. **峰值流量压测**：
   以"QPS × 3"基准流量持续压测 30 分钟。
   模拟双11 客服咨询峰值、飞书早高峰文档检索。
   观察是否出现超时、报错、数据丢失。
   验证系统抗突发能力。

3. **长时间稳定性压测**：
   以"日常峰值 × 1.5"流量持续压测 24 小时。
   监控系统指标的稳定性。
   排查内存泄漏、资源耗尽等潜在问题。

4. **故障注入压测**：
   主动注入故障。
   关闭向量数据库主节点。
   断开 GPU 节点。
   限制网络带宽。
   观察系统容错能力与恢复时间。
   验证运维应急机制有效性。

### 执行流程

1. **工具选型**：
   使用 BytePress 分布式压测工具。
   支持百万级并发请求生成。
   集成监控仪表盘实时展示压测数据。

2. **预压测验证**：
   以 1000 QPS 进行 10 分钟预压测。
   检查压测环境、用例、监控是否正常。
   出现异常则排查配置或用例问题。

3. **正式压测**：
   按顺序执行四大场景。
   每完成一个场景生成阶段性报告。
   指标达标后进入下一环节。

4. **压测后复盘**：
   对比压测指标与业务需求。
   分析未达标原因。
   输出《压测复盘报告》与优化建议。

### 核心压测指标

| 指标类别 | 指标名称 | 达标要求（核心业务） |
|---------|---------|-------------------|
| 性能 | 平均响应时间（ART） | ≤ 500ms（检索层）、≤ 1s（生成层） |
| 性能 | 99 分位响应时间 | ≤ 1.5s（检索层）、≤ 2s（生成层） |
| 可用性 | 成功响应率 | ≥ 99.99% |
| 可用性 | 故障恢复时间（RTO） | ≤ 10s（节点故障）、≤ 30s（集群故障） |
| 资源 | CPU 使用率 | ≤ 90%（生成层节点） |
| 资源 | GPU 显存占用 | ≤ 85% |
| 资源 | 数据库连接数 | ≤ 最大连接数的 80% |

### 抖音电商优化案例

**问题现象**：
并发量达 15000 QPS 时，
生成层平均响应时间从 800ms 升至 2.5s，
GPU 使用率达 98%，出现超时。

**根因定位**：
通过 ByteProfiler 分析，
云雀 - Tiny 模型单条请求推理耗时增加。
GPU 内存带宽成为瓶颈，
导致批量推理效率下降。

**优化措施**：
- 动态批处理最大批次从 32 增至 64
- GPU 显存压缩（FP16 → INT8 量化）
- 显存占用降低 50%，释放带宽资源
- 新增 2 个 GPU 节点
- ByteLB 负载均衡分散请求

**优化效果**：
15000 QPS 下生成层响应时间降至 900ms，
GPU 使用率稳定在 75%，
成功响应率恢复至 99.99%。
30000 QPS 压测时仍满足指标要求。

## 常见误区

**压测环境与生产不一致**：不同规格配置导致结果失真，须 1:1 复刻生产环境。
**仅做并发量压测**：无法发现内存泄漏等长期问题，须包含 24 小时稳定性压测。
**不做故障注入**：正常表现不等于故障时行为，须主动注入故障验证容错机制。
**压测后不复盘**：须输出复盘报告并跟踪优化措施落地。
