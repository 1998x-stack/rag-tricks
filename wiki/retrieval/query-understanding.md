# 查询理解增强

## 是什么

查询理解增强是指在执行检索之前，通过一系列技术手段深入理解用户查询的意图、完善查询内容、拆解复杂查询，从而提高检索的召回率和准确率。字节跳动的查询理解体系包含**查询预处理**、**短查询补全**、**多意图查询拆解**三个核心环节。

## 为什么重要

用户输入的原始查询往往短而不完整、包含拼写错误或歧义、混杂多个意图。未经处理的查询直接进入检索系统，会导致语义模糊、匹配偏差、信息遗漏等问题。查询理解增强是检索质量的第一道关口，统计数据表明，查询优化后检索效果可提升 10%-20%。

## 如何使用

### 查询预处理（标准化 + 补全）

**标准化处理**包含三个子步骤：
1. **纠错**：使用字节跳动自研的中文拼写纠错模型，准确率 98% 以上。例如将"飞书文挡"纠正为"飞书文档"。
2. **分词与停用词去除**：去除"的""了""吗"等无意义词，保留核心词。
3. **实体识别**：识别查询中的人名、地名、产品名等。例如将"抖音小店如何开通"中的"抖音小店"识别为产品实体，检索时优先匹配包含该实体的文档。

**短查询补全**：针对短查询（如"剪映配乐"），通过 LLM 生成扩展查询（如"剪映如何添加配乐""剪映配乐版权问题"），再将原始查询与扩展查询的向量合并进行检索，避免因查询过短导致语义模糊，提升召回率。

### 多意图查询拆解

对于包含多个意图的复杂查询（如"抖音电商如何开店，需要哪些资质，流程要多久"），采用"规则 + LLM"结合的拆解算法：

1. **规则层**：先通过标点符号（逗号、顿号）拆分查询为子句
2. **LLM 层**：对每个子句进行意图分类（如"如何开店"为流程类意图，"需要哪些资质"为条件类意图，"流程要多久"为时效类意图）
3. 针对每个子意图生成独立的检索向量，分别检索相关文档
4. 最终将各子意图的检索结果整合，为生成层提供全面的信息支持

## 常见误区

- **拼写纠错过度**：纠错模型可能将专业术语或品牌名误判为拼写错误，需维护领域白名单。
- **短查询补全引入噪声**：LLM 扩展的查询可能偏离用户原始意图，需要控制扩展查询的数量（建议 2-3 个），且扩展结果需经过相关性校验。
- **多意图拆解的粒度控制**：过度拆解会导致碎片化检索（每个子意图结果过少），需要设置最小结果数阈值，对不足阈值的子意图进行合并。
