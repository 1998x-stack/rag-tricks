# 检索触发策略

> **证据状态：Unverified。** 本页为历史整理，尚未逐条核验；公司实践、组件名称与精确指标均不能直接作为已证实事实或通用基准。见本页「来源与证据」。

## 是什么

检索触发策略决定在什么情况下启动检索流程。字节跳动采用**无条件触发**和**条件触发（LLM 意图判断 + 检索）** 两种模式，在不同业务场景中选择性地执行检索，避免不必要的检索请求，降低系统成本。

## 为什么重要

不加区分地对所有用户查询都执行检索，会带来三方面问题：一是对创意生成、情感表达类查询（如"写一段文案"），检索往往是多余的，浪费计算资源；二是对简单常识类查询（如"今天星期几"），检索和生成的双重开销远高于直接回答；三是无差别检索会增加系统延迟，影响用户体验。合理的触发策略能在保证回答质量的前提下，降低系统负载和响应时间。

## 如何使用

**无条件触发场景**：适用于事实性、时效性、专业性强的业务场景。
- 飞书知识库问答：用户发出查询后，直接进入检索流程。例如查询"飞书文档如何设置权限"，系统直接检索飞书文档手册的向量库，避免 LLM 凭记忆生成过时的操作步骤。
- 抖音电商商品参数查询：直接检索商品属性向量，确保回答的准确性和时效性。

**条件触发场景**：适用于创意生成、情感表达类场景。
- 典型场景：抖音文案创作、剪映视频脚本建议。
- 具体流程：
  1. 将用户查询输入 LLM（如字节跳动云雀模型），让模型判断查询是否需要外部知识支持，输出"需要检索"或"无需检索"
  2. 若判断为"需要检索"（如查询"2024 年抖音电商 GMV 数据"），触发检索流程
  3. 若判断为"无需检索"（如查询"写一段抖音美食视频的文案"），直接让 LLM 生成回答

**效果数据**：在内部测试中，条件触发策略使检索请求量减少 35%，降低了系统成本，同时保证了需要知识支持的查询的准确性。

## 常见误区

- **误认为条件触发一定优于无条件触发**：对于事实性场景（如产品手册查询），多一次 LLM 判断反而增加了延迟，且存在误判风险。无条件触发 + 高质量检索反而是更优方案。
- **LLM 意图判断的准确性依赖场景**：在垂直领域（如金融、医疗），通用 LLM 对是否需要检索的判断可能不准确。建议在条件触发场景中进行领域微调或补充规则逻辑。
- **忽视"无需检索"场景的回答质量**：当 LLM 直接生成回答时，仍需通过质量检查（如事实校验提示），否则可能产生幻觉内容。
