# 数据处理与准备

> **证据状态：Unverified。** 本页为历史整理，尚未逐条核验；公司实践、组件名称与精确指标均不能直接作为已证实事实或通用基准。见本页「来源与证据」。

## 概述

数据处理与准备是 RAG 系统的数据基础层，负责将原始数据转化为高质量、结构化的知识库输入。字节跳动在实践中建立了从数据收集、清洗、预处理、增强到标注分类和安全保护的全链路数据处理体系。该体系支撑着抖音客服、飞书知识库、金融研报解读等核心业务，确保后续索引构建和检索生成环节的数据质量。

## 详细知识

- [数据收集与清洗](data-collection-cleaning.md) — 数据收集渠道（内部知识库、行业数据库、公开网络资源）与数据清洗规则（去重、纠错、缺失值处理、无效数据过滤）
- [文本预处理](text-preprocessing.md) — 文本预处理流程，包括分词与词性标注、文本归一化（大小写转换、数字标准化、特殊字符处理）
- [数据增强](data-augmentation.md) — 数据增强技术：回译、同义词替换、文本摘要生成，用于扩充数据集并提升模型泛化能力
- [数据标注与分类](data-annotation.md) — 数据标注工具选择、标注规范制定与分类体系构建
- [数据安全与隐私保护](data-security.md) — 数据加密（AES）、访问控制、隐私数据处理（匿名化、去标识化）

## 核心实践

| 实践 | 场景 | 要点 | 参见 |
|------|------|------|------|
| 多通道数据收集 | 构建领域知识库 | 内部数据库 + 行业订阅 + 公开爬取三通道并行，确保数据全面性与合法性 | [数据收集与清洗](data-collection-cleaning.md) |
| 四步清洗流水线 | 刚采集的原始数据 | 去重(哈希去重)→纠错(NLTK/CoreNLP)→缺失值处理(均值填充/删除)→无效过滤(业务规则) | [数据收集与清洗](data-collection-cleaning.md) |
| 动态分块预处理 | 长文档处理 | 语义完整性优先的动态分块，替代固定512token分块，平均分块长度降至320token | [文本预处理](text-preprocessing.md)，[向量生成策略](../indexing/vector-generation-strategy.md) |
| 回译+摘要数据增强 | 训练数据不足时 | 中→英→中回译扩充表达多样性，对长文本生成多粒度摘要扩充数据形式 | [数据增强](data-augmentation.md) |
| 分类体系驱动检索 | 多分类知识库构建 | 按业务场景构建分类体系，标注数据用于检索和生成阶段的针对性处理 | [数据标注与分类](data-annotation.md)，[索引构建与优化](../indexing/indexing.md) |
