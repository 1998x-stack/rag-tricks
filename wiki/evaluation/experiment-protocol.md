# RAG 离线实验协议

> Evidence: Derived。以下是可复制的实验记录模板，阈值由实际业务填写。

## 固定输入与可复现条件

测试集至少覆盖直接事实、多证据、术语/缩写、长文档、无答案、过期信息、权限受限和恶意文档指令。按用户或文档簇拆分开发集与留出集，避免同一问法或同一资料的近重复跨集合泄漏。

每条样本保留：

| 字段 | 作用 |
|---|---|
| query_id / query / slice | 稳定 ID、问题、所属切片 |
| corpus_version / as_of | 语料快照、知识有效时间 |
| principal / allowed_sources | 测试身份与授权范围，使用脱敏标识 |
| relevant_ids / relevance_grades | 相关文档或 chunk 标注，明确粒度 |
| answerable / required_facts | 是否可回答、必须覆盖的事实 |
| reference_sources | 参考答案来源及定位 |

语料版本变化后，原来的相关性标签可能失效；先重新审核标签，不能把知识更新效果与检索算法改进混为一项。

## 实验记录模板

```yaml
experiment_id: <唯一标识>
hypothesis: <要改善的失败模式>
baseline: <提交或配置哈希>
candidate: <提交或配置哈希>
changed_variable: <本次唯一主要变化>
dataset_version: <测试集版本>
corpus_version: <语料快照>
configuration:
  chunking: <策略、长度单位、重叠、版本>
  embedding: <模型版本、维度、归一化>
  retrieval: <算法、参数、候选数、过滤位置>
  reranker: <版本或禁用、保留数>
  generation: <模型版本、模板哈希、采样参数、上下文预算>
  cache: <策略、冷启动或预热方式>
  runtime: <硬件、并发、超时、重试>
acceptance:
  primary_metric: <指标及最小改善要求>
  guardrails: <质量、权限、延迟、成本边界>
  rollback: <触发条件和恢复配置>
artifacts: <逐条结果、日志、人工复核记录路径>
conclusion: <接受、拒绝或证据不足；原因>
```

## 执行顺序

1. 在相同查询与语料上运行基线和候选，保存逐条结果，不仅保存均值。
2. 保存召回结果、重排结果、最终 Prompt 上下文和引用，以区分检索与上下文处理损失。
3. 对齐 query_id 做配对比较；对随机生成进行重复运行并报告波动。若用 bootstrap，应记录抽样单位、随机种子和区间计算方法；相关查询按用户或文档簇抽样。
4. 检查总体指标、切片、失败率和退化样本。样本不足时记录不确定性，不以单次微小波动宣布胜出。
5. 先在开发集选择参数，最后用留出集评估；反复用留出集选参数会使其失去独立性。
6. 离线通过后再做有回滚能力的灰度，观察分布变化与用户结果。灰度比例、时长和门槛预先约定，不复制历史页里的固定百分比。

## 如何判断结果

| 观察 | 下一步 |
|---|---|
| Recall 上升但答案变差 | 比较进入 Prompt 的证据、噪声和截断位置 |
| 平均质量上升但权限切片失败 | 阻止上线，优先处理授权边界 |
| 延迟下降但超时增加 | 合并检查成功率与重试成本，不能只看成功样本 |
| 自动评分上升但人工不认可 | 复核评分规则与评审偏差 |
| 改善仅出现在重复查询 | 分开报告缓存命中与未命中结果 |
