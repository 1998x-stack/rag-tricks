# RAG 指标与计分边界

## 检索指标

设某查询的相关文档集合为 R，按排名返回的前 k 个唯一文档为 S_k。先固定 document 或 chunk 粒度；同一文档的多个 chunk 不能在文档级重复计分。

| 指标 | 定义 | 注意事项 |
|---|---|---|
| Recall@k | `count(S_k ∩ R) / count(R)` | 分母是全部已标注相关文档数 |
| Precision@k | `count(S_k ∩ R) / k` | 本仓库采用固定 k 分母，返回不足 k 的空位按不相关计 |
| Hit@k | `1`（至少命中一个相关文档），否则 `0` | 不能替代多证据问题的召回率 |
| MRR@k | 首个相关结果排名的倒数；前 k 无命中为 `0`，再对查询平均 | 只关注首个命中，需说明截断 k |

Precision 与 Recall 分别度量返回结果的相关程度和相关集合的覆盖程度，参见 [Stanford IR 教材](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-unranked-retrieval-sets-1.html)。排名质量需要考虑位置；有分级相关标签时可使用 nDCG，具体增益函数与截断深度应随报告记录，参见[排序检索评估](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-ranked-retrieval-results-1.html)。

**算术示例**：已标注相关文档为 A、B、C、D，Top-3 为 A、X、B，则 Recall@3 = 2/4，Precision@3 = 2/3，Hit@3 = 1，RR@3 = 1。这不是业务 benchmark。

本仓库约定（Derived）：

- `R` 为空时 Recall 不定义，单独统计为无答案查询，不把它记成 0 或 1 混入平均值。
- 未被标注的结果与已判定不相关的结果分开记录；补标后再比较，报告标签覆盖率。
- 每条查询先计算指标再宏平均，同时报告查询数、排除数及各切片样本量。
- 去重、权限过滤和时间有效性必须在评估协议中固定；不能用越权结果提高召回指标。

## 生成指标

| 维度 | 判定问题 | 需要什么证据 |
|---|---|---|
| 证据支持度（groundedness） | 回答中的可验证断言是否被提供的上下文支持？ | 原子断言到证据片段的对应关系 |
| 答案正确性 | 回答是否符合该问题的参考事实与时间范围？ | 独立参考答案或专家标注 |
| 完整性 | 是否覆盖参考答案要求的要点？ | 必答要点列表 |
| 问题相关性 | 是否直接回应用户的问题？ | 问题与回答 |
| 引用有效性 | 引用存在、可访问，而且确实支持该断言吗？ | 文档版本、位置与访问权限 |
| 拒答质量 | 无答案时是否拒答，有答案时是否误拒？ | 可回答性标签与拒答判定 |

Microsoft 的 [RAG 评估文档](https://learn.microsoft.com/en-us/azure/foundry/concepts/evaluation-evaluators/rag-evaluators) 区分了检索过程评估与回答层面的 groundedness、相关性、完整性。上述表格是本仓库的工程化拆分，不表示采用其服务或默认分值。

**语义相似不等于事实一致**：“允许退款”和“不允许退款”主题接近但结论相反。余弦相似度适合辅助筛选，不能直接命名为事实准确率或正确性概率。证据本身过期时，回答可以忠实于证据却仍然错误。

LLM 评审需要固定模型版本、提示词和评分规则，抽样与人工复核对齐，单独记录评审失败与分歧。不要让被测方案知道留出集答案，也不要把评审模型的输出直接当成客观真值。

## 性能与成本口径

本仓库建议分别报告首 token 时间、端到端时间的 P50/P95/P99、成功率、超时率、吞吐和单位成功请求成本。注明并发、输入/输出长度、缓存命中率、硬件与限流条件。

成本应包含失败、重试、检索、重排和模型调用；离线建库成本单独列出。只统计成功请求的延迟时同时展示失败与超时数量，避免把最慢请求丢弃后得出虚假的改善。
