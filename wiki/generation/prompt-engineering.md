# Prompt Engineering 实践

> **证据状态：Unverified。** 本页为历史整理，尚未逐条核验；公司实践、组件名称与精确指标均不能直接作为已证实事实或通用基准。见本页「来源与证据」。

## 是什么

Prompt Engineering（提示工程）是设计结构化指令来引导语言模型生成符合预期回答的技术实践。在 RAG 系统中，提示工程充当着"检索信息"与"生成模型"之间的关键桥梁。字节跳动通过**标准化提示模板设计**、**动态提示优化策略**以及**模板库复用机制**，让模型更高效地利用检索信息，生成符合业务场景的高质量回答。

## 为什么重要

同样的检索信息输入不同的提示模板，生成质量差异显著。结构混乱的提示会导致模型忽略关键检索信息、生成格式不符合要求、遗漏重要约束条件。标准化模板和动态优化使提示质量可控，并使模板库复用率达到 80% 以上，减少各业务线重复开发成本，同时保证生成结果的一致性。

## 如何使用

### 标准化提示模板设计

核心模板结构包含五部分：**角色定义 → 任务指令 → 检索信息 → 格式要求 → 示例引导**。

**客服问答场景模板**：
```
【角色定义】你是字节跳动抖音电商客服专员，需基于提供的检索信息，为用户提供准确、简洁的回答，避免使用专业术语，确保用户易懂。
【任务指令】用户的问题是：{用户查询}，请结合以下检索信息，回答用户问题，不要添加检索信息外的内容。
【检索信息】
1. 检索片段 1：{检索结果 1 文本，相似度得分：xx}
2. 检索片段 2：{检索结果 2 文本，相似度得分：xx}
...
【格式要求】回答需分点说明（使用数字 1、2、3 引导），每点不超过 20 字，总长度不超过 100 字。
【示例引导】
用户查询：抖音小店入驻需多少钱？
检索信息：1. 抖音小店入驻需缴纳 2000 元保证金，不同类目可能有调整；2. 保证金可在店铺关闭后申请退还。
参考回答：1. 入驻需缴 2000 元保证金，类目不同可能调整；2. 店铺关闭后可申请退还保证金。
```

**行业报告总结场景模板**：
- 角色定义为"金融行业分析师"
- 格式要求包含核心观点（3-5 句话含关键数据）、数据支撑（指标:数值 格式并标注来源研报段落）、风险提示（政策风险、市场风险等）

**模板复用与定制**：将标准化模板封装为"提示模板库"，各业务线可基于模板库进行二次定制（如调整格式要求、补充行业特定指令），但需通过内部审核，确保模板的"结构化"不被破坏。模板库的复用率达到 80% 以上。

### 动态提示优化策略

**检索信息排序与筛选**：
当检索结果数量较多（如 Top10 片段）时，不直接将所有片段传入提示，而是：
1. 保留相似度得分 ≥ 0.7 的片段（过滤低相关信息）
2. 按文档权威性（官方 > 合作 > UGC）优先排序，同级按相似度排序
3. 对片段进行冗余合并（来自同一文档的相邻片段合并为一个），最终保留 3-5 个核心片段
在金融研报总结场景中，该策略使模型对关键数据的引用准确率提升 35%，生成总结的冗余度下降 40%。

**上下文压缩提示**：
当检索片段过长（如超过 1000 字）时，先通过轻量级模型（云雀-Tiny）对片段进行压缩，提取核心信息（关键数据、结论句），再将压缩后的信息传入提示。例如将某研报中 500 字的分析压缩为关键摘要再传入。该策略使提示长度减少 60%，模型推理速度提升 30%，同时避免长文本导致的模型注意力衰减。

**查询-信息对齐提示**：
对于多意图查询（如"抖音电商如何开店，需要哪些资质"），在提示中明确标注"查询意图-检索信息"的对应关系，引导模型针对性利用信息。模板示例：
```
【查询意图拆解】用户查询包含两个意图：1. 抖音电商开店流程；2. 开店所需资质。
【检索信息与意图对应】
- 意图 1 对应检索片段：{片段 1}
- 意图 2 对应检索片段：{片段 2}
【生成要求】请分别针对两个意图生成回答，每个意图用"意图 x："引导。
```
该方法在多意图查询场景中，使模型对各意图的信息覆盖率提升 42%，避免因意图混淆导致的回答遗漏。

## 常见误区

- **模板越详细越好**：过于冗长的模板（超过 2000 token）会挤占模型的有效上下文窗口，使模型注意力分散。模板应保持结构化但简洁。
- **忽视示例引导的质量**：示例中的任何错误（如包含了检索信息外的内容）会被模型模仿。示例必须是实际业务中验证过的"黄金回答"。
- **静态模板无法覆盖所有场景**：同样的提示模板在不同检索信息质量下表现差异巨大，需要动态策略（排序、压缩、对齐提示）配合使用。
