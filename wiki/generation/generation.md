# 生成层设计与优化

> **证据状态：Unverified。** 本页为历史整理，尚未逐条核验；公司实践、组件名称与精确指标均不能直接作为已证实事实或通用基准。见本页「来源与证据」。

## 概述

生成层是 RAG 系统面向用户的"最后一公里"，负责基于检索到的高质量信息生成准确、流畅、符合业务场景的自然语言回答。字节跳动在生成层设计中始终围绕"质量优先、效率适配、成本可控"三大原则，构建了从模型选型、提示工程、质量控制到效率优化的完整实践体系。生成层的设计直接影响用户体验和业务效果，是 RAG 系统价值变现的关键环节。

## 详细知识

- [语言模型选型与适配](model-selection.md) — 语言模型选型与适配：业务需求-模型能力-资源成本三维选型框架，典型场景选型案例（抖音客服 1.8B 云雀 Tiny、金融研报 13B 云雀 Finance），三级微调策略（Domain Fine-tuning + Task Fine-tuning + 对比学习）
- [Prompt Engineering 实践](prompt-engineering.md) — Prompt Engineering 实践：标准化模板五部分（角色定义-任务指令-检索信息-格式要求-示例引导），动态优化（检索信息排序筛选保留 3-5 个核心片段、上下文压缩减少 60% 提示长度、查询-信息对齐提示使信息覆盖率提升 42%），模板库复用率 80%+
- [生成结果质量控制](generation-quality.md) — 生成结果质量控制：事前预防（检索信息锚定使幻觉率从 12% 降至 4%、事实校验提示使数据错误率下降 38%、低置信度拒答机制）、事中监控（关键词与规则检测、实时语义检测 BERT 分类器耗时 < 100ms）、事后优化（用户反馈收集 + 人工评估体系 + 归因迭代闭环，平均分从 7.2 提升至 8.8）
- [生成效率与成本优化](generation-efficiency.md) — 生成效率与成本优化：模型量化（FP32→FP16 显存降低 50% 速度提升 40%、INT8 QAT 显存降低 75% 速度提升 2 倍）、结构化剪枝（参数量从 7B 降至 5.6B 速度提升 30%）、推理并行（张量并行 Tensor Parallelism + 批处理并行 Batch Parallelism）、资源调度（优先级调度 + ARIMA/LSTM 动态扩缩容使成本节省 45%）
- [生成层效果评估](generation-evaluation.md) — 生成层效果评估：三维评估体系（质量 + 效率 + 成本），ByteGenEval 评估平台，每日轻量 + 每周全量 + 每月复盘的评估流程

## 核心实践

| 实践 | 场景 | 要点 | 参见 |
|------|------|------|------|
| 三级微调策略 | 垂直领域专业问答 | Domain Fine-tuning（增量预训练，数据量需 ≥ 模型参数量 × 10）+ Task Fine-tuning（指令微调 + LoRA，参数量减少 90%+）+ 对比学习（正负样本区分，幻觉率从 15% 降至 5% 以下） | [语言模型选型与适配](model-selection.md) |
| 标准化提示模板 | 多业务线统一生成 | 五部分模板结构 + 模板库 80% 复用率 + 各业务线二次定制但需审核保持结构化 | [Prompt Engineering 实践](prompt-engineering.md) |
| 生成质量全链路控制 | 金融/客服等准确性敏感场景 | 事前（锚定 + 校验 + 拒答）→ 事中（关键词规则 + 语义检测）→ 事后（反馈 + 评估 + 归因迭代） | [生成结果质量控制](generation-quality.md) |
| 模型轻量化 | 高并发低延迟场景 | FP16 量化（质量损失 < 3%）→ 结构化剪枝（质量损失 < 2%）→ 动态批处理（GPU 利用率从 40% 提升至 85%）| [生成效率与成本优化](generation-efficiency.md) |
