# 数据层设计

## 是什么

数据层是 RAG 系统架构的最底层，负责存储和管理外部知识库中的数据。它是整个 RAG 系统的知识源头——数据层提供的信息质量和覆盖范围从根本上决定了 RAG 系统的能力上限。数据层的产出是下层索引层的直接输入，如果数据层的内容质量不高，索引层和检索层的优化也只能在有限范围内提升效果。

字节跳动的 RAG 数据层处理三种主要数据类型：
- **结构化数据**：数据库中的表格数据，包括用户信息、产品信息、订单信息等。可以通过 SQL 查询等方式处理，但需要转换为适合 RAG 系统处理的自然语言格式
- **半结构化数据**：XML、JSON 文件等，既有一定的结构又包含非结构化文本内容。处理半结构化数据需要结合结构化数据和文本数据的处理方法——既要解析字段结构，也要理解自由文本内容
- **非结构化数据**：文本文件、PDF 文档等，是最常见的数据类型，包括新闻文章、博客、论坛帖子、产品说明书等。文本数据本身可直接处理，但需要进行分词、去停用词、词性标注等预处理步骤

## 为什么重要

数据层是 RAG 系统的"石油层"——没有高质量的知识原料，再先进的检索算法和生成模型也无法产出满意的结果。数据层的设计直接影响：

**系统质量的根本上限** — 任何检索算法或生成模型都无法从不存在或错误的数据中产出正确答案。数据层的质量直接决定了 RAG 系统的效果天花板。在字节跳动的实践中，数据清洗和治理（去除重复数据、纠正拼写错误、处理缺失值）是 RAG 系统建设的首要任务。

**端到端的运营成本** — 数据治理不完善导致的数据冗余、过期、缺失问题，会在索引层、检索层和生成层被层层放大。例如，1 条重复数据在索引层会占用向量库存储成本，在检索层可能被重复检索并返回，在生成层因信息冗余导致回答质量下降。最终维护成本会指数级上升。

**合规与安全的基础保障** — 随着隐私法规的日益严格，数据层面的合规设计是 RAG 系统上线的前提条件。字节跳动采用的数据加密标准 AES 对敏感数据加密存储和传输，建立严格的访问控制机制（根据员工职责授予不同权限），对每一次数据访问进行详细记录和审计。

## 如何使用

字节跳动的数据层设计围绕数据来源、存储管理和湖仓架构三个方向展开：

### 数据来源与类型处理

**内部知识库** — 业务文档、技术手册、客服知识库等，直接来源于公司日常运营。这类数据与业务紧密相关，对解决特定问题具有极高价值。在智能客服场景中，内部产品使用常见问题解答文档能够帮助快速响应用户咨询。

**行业数据库** — 订阅的专业行业数据库，获取行业报告、研究论文、统计数据等权威信息。在金融业务线，通过订阅金融数据提供商的数据库获取最新市场行情、公司财报等数据。

**公开网络资源** — 利用网络爬虫技术从权威网站、新闻媒体、行业论坛等公开渠道收集信息。需严格遵守法律法规和网站使用条款。

**不同数据类型的处理策略：**
- 文本数据：分词（结巴分词改进版，支持自定义词典加入业务术语）、去停用词、词性标注（如哈工大 LTP 工具包）
- 结构化数据：通过 SQL 查询提取后，转换为自然语言描述（如"产品 A 的价格为 100 元，库存 500 件"），这种方式更适合语义检索
- 半结构化数据：解析字段结构的同时提取自由文本内容，二者独立处理后合并

### 数据湖与数据仓库协同

字节跳动采用数据湖和数据仓库相结合的架构：
- **数据湖**用于存储原始的、未经处理的数据，保留多样性和原始性。适用于全量数据的归档和探索性分析
- **数据仓库**用于存储经过清洗、转换和整合的数据，支持分析和决策。数据质量更高，适合索引层直接消费
- 协同工作模式：数据湖提供"原料仓库"，数据仓库提供"精加工产品"。RAG 系统中，数据湖作为全量知识存档，数据仓库产出高质量的子集用于索引构建

### 数据质量管理

字节跳动在数据层建立了系统化的数据质量管理机制：

**质量指标监控** — 对数据层的关键质量指标进行持续监控，包括：数据完整率（必填字段的缺失比例）、数据准确率（样本抽检的准确比例）、数据时效性（数据入库到可用的延迟）、数据一致性（不同来源之间的冲突比例）。

**数据治理流程** — 建立从数据采集、清洗、验证到发布的完整治理流程。每次数据更新需经过：采集检查（源端数据可用性验证）、清洗执行（去重、纠错、填充缺失值）、质量检验（抽样验证通过率阈值）、发布上线（更新索引层）。

**反馈闭环** — 检索层和生成层发现的数据质量问题（如检索到无关结果、生成回答引用错误数据）反馈回数据层，由数据工程师进行根因分析和数据修复。这种反馈闭环确保了数据质量持续提升而非一次性地改善。

### 数据安全性管理

在数据处理与准备过程中，字节跳动高度重视数据安全和隐私保护，建立了多层防护体系：

**数据加密** — 对敏感数据进行加密存储和传输。在数据层的数据库中和数据传输过程中，采用 AES（高级加密标准）等先进加密算法。例如，对于用户的个人信息、商业机密等数据，在存储到数据库之前进行加密处理，确保即使数据被非法获取也难以破解。

**访问控制** — 建立严格的访问控制机制，根据员工的工作职责和业务需求授予不同的访问权限。只有经过授权的人员才能访问特定数据，并且对数据的访问操作进行详细记录和审计。数据库管理员具有最高权限，而普通开发人员只能在授权范围内访问和处理与自己工作相关的数据。

**隐私数据处理** — 对于涉及用户隐私的数据，遵循严格的隐私政策和法律法规。在收集数据时明确告知数据用途和使用方式并获得用户同意。在处理数据时采用匿名化、去标识化等技术手段，去除数据中能够直接或间接识别用户身份的信息。

## 常见误区

**数据越多越好** — 不加甄别地大量收集数据会增加索引成本（更多向量需要存储）、检索噪声（无关文档干扰结果）和响应延迟（更大索引导致更慢检索）。高质量、领域相关的知识库远比大规模但质量参差不齐的知识库有效。字节跳动的实践表明，对知识库进行"减脂"（去除低质数据）带来的效果提升有时超过"增肌"（增加数据量）。

**忽略数据时效性管理** — RAG 的一个重要优势是支持实时知识更新。但如果数据层没有版本管理和过期清理机制，知识库中的过时信息会持续污染检索结果。需要建立数据时效性标签，配合索引层的冷热数据分离机制，自动将过时数据迁移至冷存储或移除。

**低估非结构化数据的处理难度** — PDF、扫描件等非结构化数据的 OCR 识别质量、表格结构恢复、段落边界识别等预处理步骤的质量，直接影响后续的嵌入向量质量和最终检索效果。字节跳动在 PDF 处理中投入了大量工程资源，包括自定义的段落分割算法和表格识别模型。

**结构化数据直接投喂** — 数据库表格不能直接用于 RAG 的语义检索。原始记录"product_id=101, price=100, stock=500"经过语义转换后变为"产品 101 的售价为 100 元，当前库存为 500 件"，这种自然语言描述更适合嵌入模型理解和检索。
