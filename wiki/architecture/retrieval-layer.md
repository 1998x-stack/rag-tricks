# 检索层设计

> **证据状态：Unverified。** 本页为历史整理，尚未逐条核验；公司实践、组件名称与精确指标均不能直接作为已证实事实或通用基准。见本页「来源与证据」。

## 是什么

检索层是 RAG 系统四层架构中的第三层，负责接收用户的自然语言问题，将其转换为向量表示后，在索引层的向量数据库中进行近似最近邻检索（ANN），返回与问题最相关的文档或文档片段。检索层是 RAG 系统中与用户查询直接交互的核心层，其效果决定了"能找到什么"。

检索层的核心任务包括三个环节：**查询理解**（将用户问题转换为适合检索的表示）、**检索执行**（在向量库中执行搜索算法）、**结果处理**（对检索结果进行排序、过滤和摘要）。这三个环节共同作用，确保输出给生成层的信息是高质量、高相关度的。

## 为什么重要

检索层是 RAG 系统中"承上启下"的关键枢纽——它同时影响系统质量和效率：

**检索质量决定生成质量的上限** — 如果检索层无法召回相关的文档片段，生成层将无法获得必要的参考信息，LLM 只能依赖自身知识，退化为纯生成模式（答案准确性和可追溯性大幅下降）。反之，高质量的检索结果使 LLM 能够充分复用外部知识，生成更准确、更有依据的回答。检索层可以看作是生成层的"燃料供给系统"。

**检索效率决定用户体验** — 检索层是用户查询路径上的第一个处理节点。字节跳动对实时业务的要求是检索平均响应时间（ART）小于 50ms，非实时业务小于 300ms。核心业务的 QPS 承载能力要求大于 10000（单集群），故障恢复时间（RTO）小于 10 秒。检索速度在很大程度上决定了用户对系统"快不快"的第一印象。

**检索成本影响系统经济性** — 在大规模 RAG 系统中，检索成本（向量计算、数据库查询）在总成本中占有显著比例。字节跳动的成本指标要求：单位向量存储成本低于 0.5 元/万条，单位检索成本低于 2 元/万次。检索层的缓存策略、负载均衡和索引压缩等优化直接关系到运营成本。

## 如何使用

### 检索算法策略

字节跳动采用多种检索算法结合的混合策略，以兼顾不同场景下的检索质量：

**余弦相似度检索** — 将用户问题和文档的向量表示进行余弦相似度计算，相似度越高说明文档与问题越相关。这是一种简单有效的通用检索方法，适用于大多数场景。余弦相似度通过计算两个向量夹角的余弦值来衡量相似程度，消除了向量长度差异的影响。

**BM25 算法检索** — 基于词频-逆文档频率（TF-IDF）的检索算法，考虑了词在文档中的出现频率和在整个文档集中的稀有程度。BM25 在处理短文本检索时效果突出，特别适合处理专有名词、编号等精确匹配场景。在专业术语密集的知识库中（如产品型号、政策编号），BM25 的精确匹配能力是向量检索的有效补充。

**混合检索策略** — 实际应用中，字节跳动通常结合多种算法以提高检索的准确率和召回率。典型的混合策略为：先使用基于余弦相似度的检索方法进行初步检索（利用语义匹配能力召回尽可能多的相关文档），再使用 BM25 算法对检索结果进行重排序（通过精确匹配能力提升排在前面的结果质量）。这种方法既利用了语义检索的广泛召回能力，又利用了精确匹配的排序精度。

**多级过滤流程（粗筛-中筛-精筛）：**
1. **粗筛**：使用布隆过滤器（Bloom Filter）快速排除不相关文档。基于文档的关键词哈希构建，误判率控制在 0.1% 以内，可过滤 70% 以上的无关数据
2. **中筛**：在向量数据库中进行 ANN 检索，使用 HNSW 索引。在抖音客服场景中，将 efConstruction（建索引时的探索深度）设为 200、efSearch（检索时的探索深度）设为 50，在保证 95% 召回率的前提下，检索速度提升 40%
3. **精筛**：对中筛返回的 Top-50 结果，计算其与查询的精确余弦相似度，按相似度排序后返回 Top-10，避免近似检索带来的误差

### 结果处理

检索层返回的原始文档片段列表需要经过三步处理才能输入生成层：

**结果排序** — 根据检索算法计算得到的相似度得分，对检索结果进行排序，将最相关的文档或文档片段排在前面。排序决定了生成模型"最先看到"的信息，对生成结果有重要影响。

**结果过滤** — 根据预设规则过滤去除不相关或低质量的结果。过滤规则包括：文档来源（是否来自权威渠道）、发布时间（是否在有效时间范围内）、文档质量评分（是否达到最低质量要求）等。良好的过滤策略可以有效降低输入生成模型的噪声比例。

**结果摘要** — 为了减少输入到生成层的信息量，提高生成效率，可以对检索结果进行摘要提取。字节跳动使用 TextRank 算法自动提取文档的关键句子作为摘要，保留核心信息的同时压缩输入长度。这不仅节省了 LLM 的 token 消耗，也减少了噪声信息的干扰。

## 检索质量评估体系

字节跳动建立了系统化的检索层评估指标，以可量化的方式监控检索效果：

**检索效果指标：**
- Recall@k（召回率）：检索返回的 Top-k 结果中，与查询相关的文档占总相关文档的比例。k 默认取 10，核心业务要求 Recall@10 >= 90%
- Precision@k（精确率）：Top-k 结果中相关文档的占比，核心业务要求 Precision@10 >= 85%
- MAP（平均准确率）：综合评估不同 k 值下的精确率，反映检索结果的整体排序质量，核心业务要求 MAP >= 88%

**性能指标：**
- ART（平均响应时间）：实时业务要求 ART <= 50ms，非实时业务要求 ART <= 300ms
- QPS 承载能力：核心业务要求单集群 QPS >= 10000
- RTO（故障恢复时间）：节点故障后恢复服务的时间，要求 RTO <= 10s

**成本指标：**
- 单位向量存储成本：低于 0.5 元/万条
- 单位检索成本：低于 2 元/万次

## 常见误区

**只依赖一种检索算法** — 余弦相似度对语义理解好但可能遗漏关键词精确匹配的结果（如产品编号"P2024-001"与"P2023-001"的向量距离过近导致混淆），BM25 的精确匹配好但无法理解同义词和上下文（无法将"轿车"与"汽车"关联）。混合策略是行业共识，不同类型数据的检索需求需要不同类型的算法来满足。

**检索 Top-k 越大越好** — 返回更多结果给生成层并不能保证更好的回答质量。过多的噪声信息会分散 LLM 的注意力，反而降低回答质量。字节跳动的经验表明，Top-k 值通常在 5-15 之间，且需要根据知识库的分散程度和数据质量进行调整。

**忽略检索结果的过滤和摘要** — 直接将原始检索结果塞入生成层是一种常见做法，但会导致生成效率降低（浪费 token 在处理无关内容上）和质量波动（噪声干扰模型注意力）。检索层应当承担信息精炼的职责。

**将检索延迟完全归咎于算法** — 检索延迟的瓶颈往往在索引层（索引类型选择不当导致查询效率低、数据分布不均导致某些分片成为热点）或基础设施层（负载均衡配置不合理、缓存命中率低）而非检索算法本身。遇到检索延迟问题时，应依次排查索引配置、缓存策略和负载均衡，而非盲目调整算法参数。
